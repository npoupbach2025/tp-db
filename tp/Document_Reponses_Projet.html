Question 2 : Analyse du schéma conceptuel — Contraintes

Le cahier des charges impose 8 contraintes métier. Pour chacune, nous analysons si elle est représentable dans le schéma UML, et comment elle sera implémentée en base de données.

C1 : Maximum 4 concours par année (1 par saison)

Représentée dans l'UML ? Non — les cardinalités UML ne permettent pas d'exprimer une limite temporelle sur le nombre d'instances par année.

Implémentation BD : Trigger BEFORE INSERT sur CONCOURS qui compte le nombre de concours existants pour l'année de dateDebut. Si ≥ 4, erreur.

Impact INSERT : Respecter 4 concours par année (2023 et 2024 dans notre jeu de données).

C2 : Un évaluateur ne peut pas évaluer plus de 8 dessins dans un même concours

Représentée dans l'UML ? Non — pas exprimable par une simple cardinalité.

Implémentation BD : Trigger BEFORE INSERT sur EVALUATION qui compte les évaluations de cet évaluateur pour le concours du dessin. Si ≥ 8, erreur.

Impact INSERT : Chaque évaluateur évalue ≤ 8 dessins par concours.

C3 : Un dessin doit être évalué par exactement 2 évaluateurs (jury)

Représentée dans l'UML ? Partiellement — la cardinalité « 2 » côté évaluateur est visible sur l'association « évalue », mais le caractère exact est difficile à imposer au niveau conceptuel.

Implémentation BD : Trigger BEFORE INSERT sur EVALUATION vérifiant que le dessin n'a pas déjà 2 évaluations. Le contrôle « exactement 2 » (pas moins) est vérifié au niveau applicatif ou lors du changement d'état du concours.

Impact INSERT : Chaque dessin a exactement 2 lignes dans EVALUATION.

C4 : Le président d'un concours ne peut pas être évaluateur ni compétiteur du même concours

Représentée dans l'UML ? Non — c'est une contrainte inter-associations qui ne peut pas être modélisée par les seules cardinalités.

Implémentation BD : Trigger BEFORE INSERT sur INSCRIPTION_COMPETITEUR_CONCOURS et INSCRIPTION_EVALUATEUR_CONCOURS vérifiant que l'utilisateur n'est pas le président du concours.

Impact INSERT : Ne jamais inscrire le président comme compétiteur ou évaluateur de son propre concours.

C5 : Un compétiteur ne peut pas déposer plus de 3 dessins dans un même concours

Représentée dans l'UML ? Non — la cardinalité « * » est trop large pour exprimer cette limite.

Implémentation BD : Trigger BEFORE INSERT sur DESSIN comptant les dessins du compétiteur dans ce concours. Si ≥ 3, erreur.

Impact INSERT : Max 3 dessins par compétiteur par concours.

C6 : Un concours doit mobiliser au moins 6 clubs

Représentée dans l'UML ? Partiellement — la cardinalité « 6..* » pourrait être indiquée sur l'association « participe », mais en pratique on laisse « * » et on contrôle autrement.

Implémentation BD : Contrôle applicatif lors du changement d'état (pas_commence → en_cours). Vérification que ≥ 6 clubs sont inscrits.

Impact INSERT : Chaque concours a au minimum 6 clubs participants (dans notre base, les 12 clubs participent à chaque concours).

C7 : Chaque club participant doit mobiliser ≥ 6 compétiteurs et ≥ 3 évaluateurs dans ce concours

Représentée dans l'UML ? Non — contrainte croisant plusieurs associations.

Implémentation BD : Contrôle applicatif effectué par le directeur du club. Vérification avant le passage en état « en_cours ».

Impact INSERT : Pour chaque club dans un concours, nous insérons au minimum 6 compétiteurs et 3 évaluateurs.

C8 : Un évaluateur d'un concours ne peut pas concourir dans ce même concours

Représentée dans l'UML ? Non — contrainte croisée entre les rôles Compétiteur et Évaluateur sur un même concours.

Implémentation BD : Trigger BEFORE INSERT sur INSCRIPTION_COMPETITEUR_CONCOURS vérifiant que l'utilisateur n'est pas inscrit comme évaluateur du même concours, et inversement.

Impact INSERT : Aucun utilisateur n'est à la fois compétiteur et évaluateur d'un même concours.

Question 3 : Le schéma logique

a) Formalisme textuel pour le schéma logique

La transformation du schéma conceptuel vers le schéma logique suit les règles classiques :

  • 1:N → clé étrangère du côté N
  • N:N → table d'association avec PK composée des deux FK
  • Héritage → table par sous-classe (PK = FK vers UTILISATEUR)
CLUB (numClub, nomClub (NN), adresse (NN), numTelephone, nombreAdherents,
      ville (NN), departement (NN), region (NN), dateCreation)

UTILISATEUR (numUtilisateur, nom (NN), prenom (NN), adresse, login (NN)(UNIQUE),
             motDePasse (NN), email, dateNaissance, numClub #FK→CLUB)

ADMINISTRATEUR (numUtilisateur #FK→UTILISATEUR, dateDebut)

DIRECTEUR (numUtilisateur #FK→UTILISATEUR, dateDebut, numClub #FK→CLUB)

PRESIDENT (numUtilisateur #FK→UTILISATEUR, prime, dateElection)

COMPETITEUR (numUtilisateur #FK→UTILISATEUR, datePremiereParticipation, categorie)

EVALUATEUR (numUtilisateur #FK→UTILISATEUR, specialite, niveau, experience)

CONCOURS (numConcours, theme (NN), dateDebut (NN), dateFin (NN),
          etat {'pas_commence','en_cours','attente','resultat','evalue'},
          description, nbMaxDessinsParCompetiteur, nbMinClubs,
          numPresident #FK→PRESIDENT)

PARTICIPATION_CLUB_CONCOURS (numClub #FK→CLUB, numConcours #FK→CONCOURS)

INSCRIPTION_COMPETITEUR_CONCOURS (numCompetiteur #FK→COMPETITEUR,
                                    numConcours #FK→CONCOURS)

INSCRIPTION_EVALUATEUR_CONCOURS (numEvaluateur #FK→EVALUATEUR,
                                   numConcours #FK→CONCOURS)

DESSIN (numDessin, commentaire, classement, dateRemise, leDessin, titre,
        numCompetiteur #FK→COMPETITEUR (NN), numConcours #FK→CONCOURS (NN))

EVALUATION (numEvaluateur #FK→EVALUATEUR, numDessin #FK→DESSIN,
            dateEvaluation, note CHECK(0..20), commentaire, appreciation)

Total : 13 tables (7 d'entités, 3 d'association N:N, 2 de contenu, 1 d'évaluation)

Question 4 : Le schéma physique

Le schéma physique MySQL est stocké dans le fichier sql/creationConcoursDessins.sql. Voici les types choisis :

-- TABLE : CLUB
CREATE TABLE CLUB (
    numClub INT AUTO_INCREMENT,
    nomClub VARCHAR(100) NOT NULL,
    adresse VARCHAR(255) NOT NULL,
    numTelephone VARCHAR(20),
    nombreAdherents INT DEFAULT 0,
    ville VARCHAR(100) NOT NULL,
    departement VARCHAR(100) NOT NULL,
    region VARCHAR(100) NOT NULL,
    dateCreation DATE,
    PRIMARY KEY (numClub)
) ENGINE=InnoDB;

-- TABLE : UTILISATEUR
CREATE TABLE UTILISATEUR (
    numUtilisateur INT AUTO_INCREMENT,
    nom VARCHAR(100) NOT NULL,
    prenom VARCHAR(100) NOT NULL,
    adresse VARCHAR(255),
    login VARCHAR(50) NOT NULL UNIQUE,
    motDePasse VARCHAR(255) NOT NULL,
    email VARCHAR(150),
    dateNaissance DATE,
    numClub INT NOT NULL,
    PRIMARY KEY (numUtilisateur),
    FOREIGN KEY (numClub) REFERENCES CLUB(numClub)
) ENGINE=InnoDB;

-- TABLE : ADMINISTRATEUR
CREATE TABLE ADMINISTRATEUR (
    numUtilisateur INT,
    dateDebut DATE NOT NULL,
    PRIMARY KEY (numUtilisateur),
    FOREIGN KEY (numUtilisateur) REFERENCES UTILISATEUR(numUtilisateur)
) ENGINE=InnoDB;

-- TABLE : DIRECTEUR
CREATE TABLE DIRECTEUR (
    numUtilisateur INT,
    dateDebut DATE NOT NULL,
    numClub INT NOT NULL,
    PRIMARY KEY (numUtilisateur),
    FOREIGN KEY (numUtilisateur) REFERENCES UTILISATEUR(numUtilisateur),
    FOREIGN KEY (numClub) REFERENCES CLUB(numClub)
) ENGINE=InnoDB;

-- TABLE : PRESIDENT
CREATE TABLE PRESIDENT (
    numUtilisateur INT,
    prime DECIMAL(10,2) DEFAULT 0.00,
    dateElection DATE,
    PRIMARY KEY (numUtilisateur),
    FOREIGN KEY (numUtilisateur) REFERENCES UTILISATEUR(numUtilisateur)
) ENGINE=InnoDB;

-- TABLE : COMPETITEUR
CREATE TABLE COMPETITEUR (
    numUtilisateur INT,
    datePremiereParticipation DATE,
    categorie VARCHAR(50) DEFAULT 'senior',
    PRIMARY KEY (numUtilisateur),
    FOREIGN KEY (numUtilisateur) REFERENCES UTILISATEUR(numUtilisateur)
) ENGINE=InnoDB;

-- TABLE : EVALUATEUR
CREATE TABLE EVALUATEUR (
    numUtilisateur INT,
    specialite VARCHAR(100) NOT NULL,
    niveau VARCHAR(50) DEFAULT 'intermediaire',
    experience INT DEFAULT 0,
    PRIMARY KEY (numUtilisateur),
    FOREIGN KEY (numUtilisateur) REFERENCES UTILISATEUR(numUtilisateur)
) ENGINE=InnoDB;

-- TABLE : CONCOURS
CREATE TABLE CONCOURS (
    numConcours INT AUTO_INCREMENT,
    theme VARCHAR(200) NOT NULL,
    dateDebut DATE NOT NULL,
    dateFin DATE NOT NULL,
    etat ENUM('pas_commence','en_cours','attente','resultat','evalue')
         NOT NULL DEFAULT 'pas_commence',
    description TEXT,
    nbMaxDessinsParCompetiteur INT DEFAULT 3,
    nbMinClubs INT DEFAULT 6,
    numPresident INT NOT NULL,
    PRIMARY KEY (numConcours),
    FOREIGN KEY (numPresident) REFERENCES PRESIDENT(numUtilisateur)
) ENGINE=InnoDB;

-- TABLE : PARTICIPATION_CLUB_CONCOURS
CREATE TABLE PARTICIPATION_CLUB_CONCOURS (
    numClub INT,
    numConcours INT,
    PRIMARY KEY (numClub, numConcours),
    FOREIGN KEY (numClub) REFERENCES CLUB(numClub),
    FOREIGN KEY (numConcours) REFERENCES CONCOURS(numConcours)
) ENGINE=InnoDB;

-- TABLE : INSCRIPTION_COMPETITEUR_CONCOURS
CREATE TABLE INSCRIPTION_COMPETITEUR_CONCOURS (
    numCompetiteur INT,
    numConcours INT,
    PRIMARY KEY (numCompetiteur, numConcours),
    FOREIGN KEY (numCompetiteur) REFERENCES COMPETITEUR(numUtilisateur),
    FOREIGN KEY (numConcours) REFERENCES CONCOURS(numConcours)
) ENGINE=InnoDB;

-- TABLE : INSCRIPTION_EVALUATEUR_CONCOURS
CREATE TABLE INSCRIPTION_EVALUATEUR_CONCOURS (
    numEvaluateur INT,
    numConcours INT,
    PRIMARY KEY (numEvaluateur, numConcours),
    FOREIGN KEY (numEvaluateur) REFERENCES EVALUATEUR(numUtilisateur),
    FOREIGN KEY (numConcours) REFERENCES CONCOURS(numConcours)
) ENGINE=InnoDB;

-- TABLE : DESSIN
CREATE TABLE DESSIN (
    numDessin INT AUTO_INCREMENT,
    commentaire TEXT,
    classement INT,
    dateRemise DATE,
    leDessin VARCHAR(500),
    titre VARCHAR(200),
    numCompetiteur INT NOT NULL,
    numConcours INT NOT NULL,
    PRIMARY KEY (numDessin),
    FOREIGN KEY (numCompetiteur) REFERENCES COMPETITEUR(numUtilisateur),
    FOREIGN KEY (numConcours) REFERENCES CONCOURS(numConcours)
) ENGINE=InnoDB;

-- TABLE : EVALUATION
CREATE TABLE EVALUATION (
    numEvaluateur INT,
    numDessin INT,
    dateEvaluation DATE,
    note INT CHECK(note >= 0 AND note <= 20),
    commentaire TEXT,
    appreciation ENUM('insuffisant','passable','bien','tres_bien','excellent'),
    PRIMARY KEY (numEvaluateur, numDessin),
    FOREIGN KEY (numEvaluateur) REFERENCES EVALUATEUR(numUtilisateur),
    FOREIGN KEY (numDessin) REFERENCES DESSIN(numDessin)
) ENGINE=InnoDB;

Choix des types :

  • INT AUTO_INCREMENT pour les identifiants (génération auto)
  • VARCHAR(n) pour les chaînes de taille connue
  • TEXT pour les commentaires et descriptions (taille variable)
  • DATE pour les dates
  • DECIMAL(10,2) pour les montants (prime du président)
  • ENUM pour les valeurs contraintes (état concours, catégorie, etc.)
  • CHECK pour la contrainte de note entre 0 et 20

Question 6 : Interrogation de la BD — 10 Requêtes SQL

Requête 1 (imposée) — Compétiteurs ayant participé en 2024

En français : Afficher le nom, l'adresse et l'âge de tous les compétiteurs qui ont participé à un concours en 2024. Afficher aussi la description du concours, la date de début et la date de fin, le club du compétiteur, le département et la région.

SELECT
    u.nom, u.adresse,
    TIMESTAMPDIFF(YEAR, u.dateNaissance, CURDATE()) AS age,
    co.description, co.dateDebut, co.dateFin,
    cl.nomClub, cl.departement, cl.region
FROM UTILISATEUR u
JOIN COMPETITEUR c ON u.numUtilisateur = c.numUtilisateur
JOIN INSCRIPTION_COMPETITEUR_CONCOURS icc ON c.numUtilisateur = icc.numCompetiteur
JOIN CONCOURS co ON icc.numConcours = co.numConcours
JOIN CLUB cl ON u.numClub = cl.numClub
WHERE YEAR(co.dateDebut) = 2024
ORDER BY u.nom, co.dateDebut;

Requête 2 (imposée) — Dessins évalués en 2023 par note croissante

En français : Afficher par ordre croissant de la note tous les dessins évalués en 2023 : numéro du dessin, note attribuée, nom du compétiteur, description et thème du concours.

SELECT
    d.numDessin, ev.note,
    u.nom AS nom_competiteur,
    co.description, co.theme
FROM DESSIN d
JOIN EVALUATION ev ON d.numDessin = ev.numDessin
JOIN CONCOURS co ON d.numConcours = co.numConcours
JOIN UTILISATEUR u ON d.numCompetiteur = u.numUtilisateur
WHERE YEAR(ev.dateEvaluation) = 2023
ORDER BY ev.note ASC;

Requête 3 (imposée) — Informations détaillées de tous les dessins évalués

En français : Afficher le numéro, l'année et la description du concours ; le nom du compétiteur ; le numéro et le commentaire du dessin ; la note et le commentaire de l'évaluation ; le nom de l'évaluateur.

SELECT
    d.numDessin,
    YEAR(co.dateDebut) AS annee,
    co.description,
    CONCAT(u_comp.nom, ' ', u_comp.prenom) AS auteur,
    d.commentaire AS commentaire_dessin,
    ev.note,
    ev.commentaire AS commentaire_evaluation,
    CONCAT(u_eval.nom, ' ', u_eval.prenom) AS evaluateur
FROM DESSIN d
JOIN CONCOURS co ON d.numConcours = co.numConcours
JOIN UTILISATEUR u_comp ON d.numCompetiteur = u_comp.numUtilisateur
JOIN EVALUATION ev ON d.numDessin = ev.numDessin
JOIN UTILISATEUR u_eval ON ev.numEvaluateur = u_eval.numUtilisateur
ORDER BY co.numConcours, d.numDessin;

Requête 4 (imposée) — Compétiteurs ayant participé à TOUS les concours 2023-2024

En français : Nom, prénom et âge des compétiteurs qui ont participé à tous les concours organisés en 2023 et 2024, triés par âge croissant. Il s'agit d'une division relationnelle.

SELECT
    u.nom, u.prenom,
    TIMESTAMPDIFF(YEAR, u.dateNaissance, CURDATE()) AS age
FROM UTILISATEUR u
JOIN COMPETITEUR c ON u.numUtilisateur = c.numUtilisateur
JOIN INSCRIPTION_COMPETITEUR_CONCOURS icc ON c.numUtilisateur = icc.numCompetiteur
JOIN CONCOURS co ON icc.numConcours = co.numConcours
WHERE YEAR(co.dateDebut) IN (2023, 2024)
GROUP BY u.numUtilisateur, u.nom, u.prenom, u.dateNaissance
HAVING COUNT(DISTINCT co.numConcours) = (
    SELECT COUNT(*) FROM CONCOURS WHERE YEAR(dateDebut) IN (2023, 2024)
)
ORDER BY age ASC;

Requête 5 (imposée) — Région avec la meilleure moyenne

En français : Nom de la région qui a la meilleure moyenne des notes des dessins proposés. Afficher la région et la moyenne.

SELECT
    cl.region,
    AVG(ev.note) AS moyenne_notes
FROM EVALUATION ev
JOIN DESSIN d ON ev.numDessin = d.numDessin
JOIN UTILISATEUR u ON d.numCompetiteur = u.numUtilisateur
JOIN CLUB cl ON u.numClub = cl.numClub
GROUP BY cl.region
ORDER BY moyenne_notes DESC
LIMIT 1;

Requête 6 (libre) — Classement final d'un concours (concours 1)

En français : Classement final d'un concours évalué — moyenne des 2 notes par dessin, tri décroissant avec rang.

SELECT
    d.numDessin, d.titre,
    CONCAT(u.nom, ' ', u.prenom) AS competiteur,
    cl.nomClub,
    AVG(ev.note) AS moyenne,
    RANK() OVER (ORDER BY AVG(ev.note) DESC) AS classement
FROM DESSIN d
JOIN EVALUATION ev ON d.numDessin = ev.numDessin
JOIN UTILISATEUR u ON d.numCompetiteur = u.numUtilisateur
JOIN CLUB cl ON u.numClub = cl.numClub
WHERE d.numConcours = 1
GROUP BY d.numDessin, d.titre, u.nom, u.prenom, cl.nomClub
ORDER BY moyenne DESC;

Requête 7 (libre) — Nombre de dessins par club et par concours

En français : Nombre de dessins soumis par club et par concours.

SELECT
    cl.nomClub, co.theme AS concours,
    COUNT(d.numDessin) AS nb_dessins
FROM CLUB cl
JOIN UTILISATEUR u ON cl.numClub = u.numClub
JOIN DESSIN d ON u.numUtilisateur = d.numCompetiteur
JOIN CONCOURS co ON d.numConcours = co.numConcours
GROUP BY cl.numClub, cl.nomClub, co.numConcours, co.theme
ORDER BY co.numConcours, cl.nomClub;

Requête 8 (libre) — Taux de participation par concours

En français : Nombre de compétiteurs inscrits par concours et pourcentage de participation.

SELECT
    co.numConcours, co.theme, co.etat,
    COUNT(icc.numCompetiteur) AS nb_competiteurs,
    (SELECT COUNT(*) FROM COMPETITEUR) AS total_competiteurs,
    ROUND(COUNT(icc.numCompetiteur) * 100.0
          / (SELECT COUNT(*) FROM COMPETITEUR), 1) AS taux_participation_pct
FROM CONCOURS co
LEFT JOIN INSCRIPTION_COMPETITEUR_CONCOURS icc
  ON co.numConcours = icc.numConcours
GROUP BY co.numConcours, co.theme, co.etat
ORDER BY co.numConcours;

Requête 9 (libre) — Dessins en attente d'évaluation complète

En français : Concours en attente dont il manque des évaluations (dessins pas encore évalués par 2 évaluateurs).

SELECT
    co.numConcours, co.theme,
    d.numDessin, d.titre,
    COUNT(ev.numEvaluateur) AS nb_evaluations,
    (2 - COUNT(ev.numEvaluateur)) AS evaluations_manquantes
FROM CONCOURS co
JOIN DESSIN d ON co.numConcours = d.numConcours
LEFT JOIN EVALUATION ev ON d.numDessin = ev.numDessin
WHERE co.etat = 'attente'
GROUP BY co.numConcours, co.theme, d.numDessin, d.titre
HAVING COUNT(ev.numEvaluateur) < 2
ORDER BY co.numConcours, d.numDessin;

Requête 10 (libre) — Évaluateurs les plus chargés par concours

En français : Liste des évaluateurs ayant évalué le plus de dessins dans un concours, avec le nombre de places restantes (max 8).

SELECT
    co.numConcours, co.theme,
    CONCAT(u.nom, ' ', u.prenom) AS evaluateur,
    COUNT(ev.numDessin) AS nb_dessins_evalues,
    (8 - COUNT(ev.numDessin)) AS places_restantes
FROM EVALUATION ev
JOIN DESSIN d ON ev.numDessin = d.numDessin
JOIN CONCOURS co ON d.numConcours = co.numConcours
JOIN UTILISATEUR u ON ev.numEvaluateur = u.numUtilisateur
GROUP BY co.numConcours, co.theme, ev.numEvaluateur, u.nom, u.prenom
HAVING COUNT(ev.numDessin) >= 3
ORDER BY nb_dessins_evalues DESC, co.numConcours;

Triggers (5)

Trigger 1 : Max 3 dessins par compétiteur par concours

CREATE TRIGGER trg_max_3_dessins_par_competiteur
BEFORE INSERT ON DESSIN
FOR EACH ROW
BEGIN
    DECLARE nb_dessins INT;
    SELECT COUNT(*) INTO nb_dessins
    FROM DESSIN
    WHERE numCompetiteur = NEW.numCompetiteur
      AND numConcours = NEW.numConcours;
    IF nb_dessins >= 3 THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'Max 3 dessins par compétiteur par concours.';
    END IF;
END;

Trigger 2 : Max 8 évaluations par évaluateur par concours

CREATE TRIGGER trg_max_8_evaluations_par_evaluateur
BEFORE INSERT ON EVALUATION
FOR EACH ROW
BEGIN
    DECLARE nb_evals INT;
    DECLARE v_numConcours INT;
    SELECT numConcours INTO v_numConcours
    FROM DESSIN WHERE numDessin = NEW.numDessin;
    SELECT COUNT(*) INTO nb_evals
    FROM EVALUATION ev
    JOIN DESSIN d ON ev.numDessin = d.numDessin
    WHERE ev.numEvaluateur = NEW.numEvaluateur
      AND d.numConcours = v_numConcours;
    IF nb_evals >= 8 THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'Max 8 évaluations par évaluateur par concours.';
    END IF;
END;

Trigger 3 : Max 2 évaluations par dessin

CREATE TRIGGER trg_max_2_evaluations_par_dessin
BEFORE INSERT ON EVALUATION
FOR EACH ROW
BEGIN
    DECLARE nb_evals_dessin INT;
    SELECT COUNT(*) INTO nb_evals_dessin
    FROM EVALUATION WHERE numDessin = NEW.numDessin;
    IF nb_evals_dessin >= 2 THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'Un dessin ne peut pas avoir plus de 2 évaluations.';
    END IF;
END;

Trigger 4 : Président ne peut pas être compétiteur du même concours

CREATE TRIGGER trg_president_pas_competiteur
BEFORE INSERT ON INSCRIPTION_COMPETITEUR_CONCOURS
FOR EACH ROW
BEGIN
    DECLARE v_president INT;
    SELECT numPresident INTO v_president
    FROM CONCOURS WHERE numConcours = NEW.numConcours;
    IF NEW.numCompetiteur = v_president THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'Le président ne peut pas être compétiteur de son concours.';
    END IF;
END;

Trigger 5 : Évaluateur ne peut pas concourir dans le même concours

CREATE TRIGGER trg_evaluateur_pas_competiteur
BEFORE INSERT ON INSCRIPTION_COMPETITEUR_CONCOURS
FOR EACH ROW
BEGIN
    DECLARE nb_eval INT;
    SELECT COUNT(*) INTO nb_eval
    FROM INSCRIPTION_EVALUATEUR_CONCOURS
    WHERE numEvaluateur = NEW.numCompetiteur
      AND numConcours = NEW.numConcours;
    IF nb_eval > 0 THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT = 'Un évaluateur ne peut pas concourir dans le même concours.';
    END IF;
END;

Question 7 : Interface WEB

L'interface web a été développée avec les technologies suivantes :

  • Frontend : React 18, TypeScript, Tailwind CSS, shadcn/ui, Recharts
  • Backend : Node.js, Express, SQLite (sql.js)
  • Architecture : SPA avec API REST, 14 pages, rôle-based access control

1) Page d'authentification

La page de connexion permet à un utilisateur de s'authentifier avec son login et son mot de passe. Le système identifie automatiquement le rôle de l'utilisateur (administrateur, directeur, président, compétiteur, évaluateur) et redirige vers la page appropriée.

L'interface présente un formulaire moderne avec validation en temps réel, un message d'erreur clair en cas d'identifiants incorrects, et des comptes de démonstration affichés pour faciliter les tests.
