Question 2 : Analyse du schéma conceptuel

Le cahier des charges impose 8 contraintes métier. Pour chacune, nous précisons si elle est explicitement définie dans le schéma conceptuel proposé, pourquoi, et comment elle sera implémentée en base de données.

Analyse des contraintes imposées

Contrainte 1 : Il ne peut y avoir que 4 concours par année (1 concours par saison)

Représentée dans le schéma UML ? Non — Les cardinalités UML ne permettent pas d'exprimer une limite temporelle sur le nombre d'instances par période. C'est une contrainte dynamique dépendant de la valeur de l'attribut dateDebut.

Implémentation en BD : Trigger BEFORE INSERT sur la table CONCOURS qui compte le nombre de concours existants pour l'année de la date de début. Si le compte atteint 4, l'insertion est rejetée avec un message d'erreur.

Contrainte 2 : Un évaluateur ne pourra évaluer plus de 8 dessins en tout dans un même concours

Représentée dans le schéma UML ? Non — Cette limite numérique ne peut pas être exprimée par une simple cardinalité sur l'association.

Implémentation en BD : Trigger BEFORE INSERT sur la table EVALUATION qui joint avec DESSIN pour retrouver le concours, puis compte les évaluations de cet évaluateur dans ce concours. Si le total atteint 8, l'insertion est rejetée.

Contrainte 3 : Un dessin doit être évalué par deux évaluateurs qui constituent un Jury

Représentée dans le schéma UML ? Partiellement — La cardinalité « 2 » côté évaluateur est visible sur l'association « évalue », mais le caractère exactement 2 est difficile à imposer au niveau conceptuel.

Implémentation en BD : Trigger BEFORE INSERT sur EVALUATION vérifiant que le dessin n'a pas déjà 2 évaluations. Le contrôle « au moins 2 » est géré au niveau applicatif lors du changement d'état du concours.

Contrainte 4 : Tout président d'un concours ne pourra pas être évaluateur ou compétiteur de ce même concours

Représentée dans le schéma UML ? Non — C'est une contrainte inter-associations qui croise les rôles Président, Compétiteur et Évaluateur sur un même concours. Elle ne peut pas être modélisée par les seules cardinalités UML.

Implémentation en BD : Trigger BEFORE INSERT sur les tables INSCRIPTION_COMPETITEUR_CONCOURS et INSCRIPTION_EVALUATEUR_CONCOURS vérifiant que l'utilisateur n'est pas le président du concours concerné.

Contrainte 5 : Tout compétiteur ne peut pas déposer plus de trois dessins dans un même concours donné

Représentée dans le schéma UML ? Non — La cardinalité « * » entre Compétiteur et Dessin est trop large pour exprimer cette limite de 3.

Implémentation en BD : Trigger BEFORE INSERT sur la table DESSIN comptant le nombre de dessins du compétiteur dans ce concours. Si le total atteint 3, l'insertion est rejetée.

Contrainte 6 : Un concours pour être organisé doit mobiliser au moins 6 clubs

Représentée dans le schéma UML ? Partiellement — La cardinalité « 6..* » pourrait être indiquée sur l'association « participe », mais en pratique la vérification porte sur le moment du changement d'état.

Implémentation en BD : Contrôle applicatif lors du passage de l'état pas_commence à en_cours. Vérification que ≥ 6 clubs sont inscrits au concours.

Contrainte 7 : Tout club qui participe à un concours donné doit mobiliser au moins 6 compétiteurs et 3 évaluateurs

Représentée dans le schéma UML ? Non — Contrainte croisant plusieurs associations (Club-Concours, Compétiteur-Concours, Évaluateur-Concours) avec une condition sur l'appartenance au club.

Implémentation en BD : Contrôle applicatif géré par le directeur du club. Vérification avant la validation du changement d'état du concours.

Contrainte 8 : Un évaluateur d'un concours ne peut pas concourir dans celui-ci

Représentée dans le schéma UML ? Non — Contrainte croisée entre les rôles Compétiteur et Évaluateur pour un même concours, non modélisable par des cardinalités.

Implémentation en BD : Trigger BEFORE INSERT sur INSCRIPTION_COMPETITEUR_CONCOURS vérifiant que l'utilisateur n'est pas inscrit comme évaluateur du même concours, et inversement sur INSCRIPTION_EVALUATEUR_CONCOURS.

Question 3 : Le schéma logique

En suivant les règles de passage d'un schéma conceptuel vers un schéma logique de bases de données relationnelles, nous proposons ci-dessous le schéma logique correspondant au schéma conceptuel. Les clés étrangères et les clés primaires sont bien désignées dans le formalisme textuel.

a) Formalisme textuel pour le schéma logique

La transformation du schéma conceptuel vers le schéma logique relationnel suit les règles classiques :

  • Association 1:N → clé étrangère du côté N (ex : numClub dans UTILISATEUR)
  • Association N:N → table d'association avec clé primaire composée des deux clés étrangères
  • Héritage → table par sous-classe, avec PK = FK vers la table UTILISATEUR
  • Classe d'association → table avec PK composée + attributs propres (EVALUATION)
Légende : attribut souligné = clé primaire (PK)  |  #FK→TABLE = clé étrangère  |  (NN) = NOT NULL  |  (UNIQUE) = contrainte d'unicité 
CLUB (numClub, nomClub (NN), adresse (NN), numTelephone, nombreAdherents,
      ville (NN), departement (NN), region (NN), dateCreation)

UTILISATEUR (numUtilisateur, nom (NN), prenom (NN), adresse,
             login (NN)(UNIQUE), motDePasse (NN), email, dateNaissance,
             numClub #FK→CLUB)

ADMINISTRATEUR (numUtilisateur #FK→UTILISATEUR, dateDebut)

DIRECTEUR (numUtilisateur #FK→UTILISATEUR, dateDebut,
           numClub #FK→CLUB)

PRESIDENT (numUtilisateur #FK→UTILISATEUR, prime, dateElection)

COMPETITEUR (numUtilisateur #FK→UTILISATEUR,
             datePremiereParticipation, categorie)

EVALUATEUR (numUtilisateur #FK→UTILISATEUR, specialite, niveau,
            experience)

CONCOURS (numConcours, theme (NN), dateDebut (NN), dateFin (NN),
          etat {'pas_commence','en_cours','attente','resultat','evalue'},
          description, nbMaxDessinsParCompetiteur, nbMinClubs,
          numPresident #FK→PRESIDENT)

PARTICIPATION_CLUB_CONCOURS (numClub #FK→CLUB,
                               numConcours #FK→CONCOURS)

INSCRIPTION_COMPETITEUR_CONCOURS (numCompetiteur #FK→COMPETITEUR,
                                    numConcours #FK→CONCOURS)

INSCRIPTION_EVALUATEUR_CONCOURS (numEvaluateur #FK→EVALUATEUR,
                                   numConcours #FK→CONCOURS)

DESSIN (numDessin, commentaire, classement, dateRemise, leDessin,
        titre, numCompetiteur #FK→COMPETITEUR (NN),
        numConcours #FK→CONCOURS (NN))

EVALUATION (numEvaluateur #FK→EVALUATEUR, numDessin #FK→DESSIN,
            dateEvaluation, note CHECK(0..20), commentaire, appreciation)

Total : 13 tables — 7 tables d'entités (dont 5 issue de l'héritage), 3 tables d'association N:N, 1 table de contenu (DESSIN), 1 table de lien (CONCOURS→PRESIDENT), 1 classe d'association (EVALUATION).

Question 4 : Le schéma physique

À partir du schéma logique proposé, nous avons déduit le schéma physique conforme à MySQL/PHPMyAdmin. Les types des différents attributs ont été judicieusement choisis. Le fichier creationConcoursDessins.sql est déposé dans l'archive.

Script de création complet

-- ============================================================
-- Schéma physique : Création de la base de données
-- Projet : Plateforme de gestion des concours de dessins
-- CNAM-ESAIP 2025-2026
-- ============================================================

DROP DATABASE IF EXISTS concours_dessins;
CREATE DATABASE concours_dessins
  CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
USE concours_dessins;

-- TABLE : CLUB
CREATE TABLE CLUB (
    numClub              INT AUTO_INCREMENT,
    nomClub              VARCHAR(100) NOT NULL,
    adresse              VARCHAR(255) NOT NULL,
    numTelephone         VARCHAR(20),
    nombreAdherents      INT DEFAULT 0,
    ville                VARCHAR(100) NOT NULL,
    departement          VARCHAR(100) NOT NULL,
    region               VARCHAR(100) NOT NULL,
    dateCreation         DATE,
    PRIMARY KEY (numClub)
) ENGINE=InnoDB;

-- TABLE : UTILISATEUR (super-classe de l'héritage)
CREATE TABLE UTILISATEUR (
    numUtilisateur       INT AUTO_INCREMENT,
    nom                  VARCHAR(100) NOT NULL,
    prenom               VARCHAR(100) NOT NULL,
    adresse              VARCHAR(255),
    login                VARCHAR(50) NOT NULL UNIQUE,
    motDePasse           VARCHAR(255) NOT NULL,
    email                VARCHAR(150),
    dateNaissance        DATE,
    numClub              INT NOT NULL,
    PRIMARY KEY (numUtilisateur),
    FOREIGN KEY (numClub) REFERENCES CLUB(numClub)
) ENGINE=InnoDB;

-- TABLE : ADMINISTRATEUR (héritage de UTILISATEUR)
CREATE TABLE ADMINISTRATEUR (
    numUtilisateur       INT,
    dateDebut            DATE NOT NULL,
    PRIMARY KEY (numUtilisateur),
    FOREIGN KEY (numUtilisateur) REFERENCES UTILISATEUR(numUtilisateur)
) ENGINE=InnoDB;

-- TABLE : DIRECTEUR (héritage de UTILISATEUR)
CREATE TABLE DIRECTEUR (
    numUtilisateur       INT,
    dateDebut            DATE NOT NULL,
    numClub              INT NOT NULL,
    PRIMARY KEY (numUtilisateur),
    FOREIGN KEY (numUtilisateur) REFERENCES UTILISATEUR(numUtilisateur),
    FOREIGN KEY (numClub) REFERENCES CLUB(numClub)
) ENGINE=InnoDB;

-- TABLE : PRESIDENT (héritage de UTILISATEUR)
CREATE TABLE PRESIDENT (
    numUtilisateur       INT,
    prime                DECIMAL(10,2) DEFAULT 0.00,
    dateElection         DATE,
    PRIMARY KEY (numUtilisateur),
    FOREIGN KEY (numUtilisateur) REFERENCES UTILISATEUR(numUtilisateur)
) ENGINE=InnoDB;

-- TABLE : COMPETITEUR (héritage de UTILISATEUR)
CREATE TABLE COMPETITEUR (
    numUtilisateur       INT,
    datePremiereParticipation DATE,
    categorie            VARCHAR(50) DEFAULT 'senior',
    PRIMARY KEY (numUtilisateur),
    FOREIGN KEY (numUtilisateur) REFERENCES UTILISATEUR(numUtilisateur)
) ENGINE=InnoDB;

-- TABLE : EVALUATEUR (héritage de UTILISATEUR)
CREATE TABLE EVALUATEUR (
    numUtilisateur       INT,
    specialite           VARCHAR(100) NOT NULL,
    niveau               VARCHAR(50) DEFAULT 'intermediaire',
    experience           INT DEFAULT 0,
    PRIMARY KEY (numUtilisateur),
    FOREIGN KEY (numUtilisateur) REFERENCES UTILISATEUR(numUtilisateur)
) ENGINE=InnoDB;

-- TABLE : CONCOURS
CREATE TABLE CONCOURS (
    numConcours          INT AUTO_INCREMENT,
    theme                VARCHAR(200) NOT NULL,
    dateDebut            DATE NOT NULL,
    dateFin              DATE NOT NULL,
    etat                 ENUM('pas_commence','en_cours','attente',
                              'resultat','evalue')
                         NOT NULL DEFAULT 'pas_commence',
    description          TEXT,
    nbMaxDessinsParCompetiteur INT DEFAULT 3,
    nbMinClubs           INT DEFAULT 6,
    numPresident         INT NOT NULL,
    PRIMARY KEY (numConcours),
    FOREIGN KEY (numPresident) REFERENCES PRESIDENT(numUtilisateur)
) ENGINE=InnoDB;

-- TABLE : PARTICIPATION_CLUB_CONCOURS (N:N)
CREATE TABLE PARTICIPATION_CLUB_CONCOURS (
    numClub              INT,
    numConcours          INT,
    PRIMARY KEY (numClub, numConcours),
    FOREIGN KEY (numClub) REFERENCES CLUB(numClub),
    FOREIGN KEY (numConcours) REFERENCES CONCOURS(numConcours)
) ENGINE=InnoDB;

-- TABLE : INSCRIPTION_COMPETITEUR_CONCOURS (N:N)
CREATE TABLE INSCRIPTION_COMPETITEUR_CONCOURS (
    numCompetiteur       INT,
    numConcours          INT,
    PRIMARY KEY (numCompetiteur, numConcours),
    FOREIGN KEY (numCompetiteur) REFERENCES COMPETITEUR(numUtilisateur),
    FOREIGN KEY (numConcours) REFERENCES CONCOURS(numConcours)
) ENGINE=InnoDB;

-- TABLE : INSCRIPTION_EVALUATEUR_CONCOURS (N:N)
CREATE TABLE INSCRIPTION_EVALUATEUR_CONCOURS (
    numEvaluateur        INT,
    numConcours          INT,
    PRIMARY KEY (numEvaluateur, numConcours),
    FOREIGN KEY (numEvaluateur) REFERENCES EVALUATEUR(numUtilisateur),
    FOREIGN KEY (numConcours) REFERENCES CONCOURS(numConcours)
) ENGINE=InnoDB;

-- TABLE : DESSIN
CREATE TABLE DESSIN (
    numDessin            INT AUTO_INCREMENT,
    commentaire          TEXT,
    classement           INT DEFAULT NULL,
    dateRemise           DATE NOT NULL,
    leDessin             VARCHAR(255),
    titre                VARCHAR(200) NOT NULL,
    numCompetiteur       INT NOT NULL,
    numConcours          INT NOT NULL,
    PRIMARY KEY (numDessin),
    FOREIGN KEY (numCompetiteur) REFERENCES COMPETITEUR(numUtilisateur),
    FOREIGN KEY (numConcours) REFERENCES CONCOURS(numConcours)
) ENGINE=InnoDB;

-- TABLE : EVALUATION (classe d'association)
CREATE TABLE EVALUATION (
    numEvaluateur        INT,
    numDessin            INT,
    dateEvaluation       DATE NOT NULL,
    note                 INT NOT NULL CHECK (note >= 0 AND note <= 20),
    commentaire          TEXT,
    appreciation         VARCHAR(50),
    PRIMARY KEY (numEvaluateur, numDessin),
    FOREIGN KEY (numEvaluateur) REFERENCES EVALUATEUR(numUtilisateur),
    FOREIGN KEY (numDessin) REFERENCES DESSIN(numDessin)
) ENGINE=InnoDB;

Question 6 : Interrogation de la Base de Données (Requêtes SQL)

Nous proposons 10 requêtes SQL permettant de répondre aux attentes du cahier des charges. Parmi les 10, les 5 premières sont imposées et les 5 suivantes sont libres. De plus, nous proposons 5 triggers permettant de prendre en compte les contraintes et les règles métiers du cahier des charges.

Chaque requête est exprimée en français puis en langage SQL. Toutes les requêtes ont été exécutées et validées sous MySQL. Chaque requête SQL est dans un fichier séparé (requete1.sql, requete2.sql, …, requete10.sql) déposé dans l'archive.

Requête 1 (imposée)

Afficher le nom et l'adresse et l'âge de tous les compétiteurs qui ont participé dans un concours en 2024. Afficher aussi la description du concours la date de début et la date de fin. Le club du compétiteur, le département et la région.

SELECT
    u.nom,
    u.adresse,
    TIMESTAMPDIFF(YEAR, u.dateNaissance, CURDATE()) AS age,
    co.description,
    co.dateDebut,
    co.dateFin,
    cl.nomClub,
    cl.departement,
    cl.region
FROM UTILISATEUR u
JOIN COMPETITEUR c ON u.numUtilisateur = c.numUtilisateur
JOIN INSCRIPTION_COMPETITEUR_CONCOURS icc
    ON c.numUtilisateur = icc.numCompetiteur
JOIN CONCOURS co ON icc.numConcours = co.numConcours
JOIN CLUB cl ON u.numClub = cl.numClub
WHERE YEAR(co.dateDebut) = 2024
ORDER BY u.nom, co.dateDebut;

Requête 2 (imposée)

Afficher par ordre croissant de la note tous les dessins qui ont été évalués en 2023. Afficher : le numéro du dessin et la note attribuée, le nom du compétiteur, la description du concours et le thème du concours.

SELECT
    d.numDessin,
    ev.note,
    u.nom AS nom_competiteur,
    co.description,
    co.theme
FROM DESSIN d
JOIN EVALUATION ev ON d.numDessin = ev.numDessin
JOIN CONCOURS co ON d.numConcours = co.numConcours
JOIN UTILISATEUR u ON d.numCompetiteur = u.numUtilisateur
WHERE YEAR(ev.dateEvaluation) = 2023
ORDER BY ev.note ASC;

Requête 3 (imposée)

Afficher des informations sur tous les dessins qui ont été évalués : le numéro, l'année, la description du concours ; le nom du compétiteur ayant proposé le dessin ; le numéro et le commentaire du dessin ; la note et le commentaire de l'évaluation ; le nom de l'évaluateur.

SELECT
    d.numDessin,
    YEAR(co.dateDebut) AS annee,
    co.description,
    CONCAT(u_comp.nom, ' ', u_comp.prenom) AS auteur,
    d.commentaire AS commentaire_dessin,
    ev.note,
    ev.commentaire AS commentaire_evaluation,
    CONCAT(u_eval.nom, ' ', u_eval.prenom) AS evaluateur
FROM DESSIN d
JOIN CONCOURS co ON d.numConcours = co.numConcours
JOIN UTILISATEUR u_comp ON d.numCompetiteur = u_comp.numUtilisateur
JOIN EVALUATION ev ON d.numDessin = ev.numDessin
JOIN UTILISATEUR u_eval ON ev.numEvaluateur = u_eval.numUtilisateur
ORDER BY co.numConcours, d.numDessin;

Requête 4 (imposée)

Nom, prénom et âge des compétiteurs qui ont participé à tous les concours qui ont été organisés en 2023 et 2024. L'affichage doit se faire dans l'ordre croissant des âges. Il s'agit d'une division relationnelle.

SELECT
    u.nom,
    u.prenom,
    TIMESTAMPDIFF(YEAR, u.dateNaissance, CURDATE()) AS age
FROM UTILISATEUR u
JOIN COMPETITEUR c ON u.numUtilisateur = c.numUtilisateur
JOIN INSCRIPTION_COMPETITEUR_CONCOURS icc
    ON c.numUtilisateur = icc.numCompetiteur
JOIN CONCOURS co ON icc.numConcours = co.numConcours
WHERE YEAR(co.dateDebut) IN (2023, 2024)
GROUP BY u.numUtilisateur, u.nom, u.prenom, u.dateNaissance
HAVING COUNT(DISTINCT co.numConcours) = (
    SELECT COUNT(*)
    FROM CONCOURS
    WHERE YEAR(dateDebut) IN (2023, 2024)
)
ORDER BY age ASC;
Explication : Cette requête utilise le principe de la division relationnelle. On regroupe par compétiteur et on ne conserve que ceux dont le nombre de concours distincts (2023-2024) auxquels ils sont inscrits est égal au nombre total de concours de ces deux années (8). Seuls les compétiteurs inscrits à tous les concours sont retournés.

Requête 5 (imposée)

Nom de la région qui a la meilleure moyenne des notes des dessins proposés. Afficher le nom de la région et la moyenne des notes de cette région.

SELECT
    cl.region,
    AVG(ev.note) AS moyenne_notes
FROM EVALUATION ev
JOIN DESSIN d ON ev.numDessin = d.numDessin

ORDER BY moyenne_notes DESC

Requête 6 (libre) — Classement final d'un concours

Classement final d'un concours évalué : moyenne des 2 notes par dessin, tri décroissant avec rang. Exemple pour le concours n° 1.

SELECT
    d.numDessin,
    d.titre,
    CONCAT(u.nom, ' ', u.prenom) AS competiteur,
    cl.nomClub,
    AVG(ev.note) AS moyenne,
    RANK() OVER (ORDER BY AVG(ev.note) DESC) AS classement
FROM DESSIN d
JOIN EVALUATION ev ON d.numDessin = ev.numDessin
JOIN UTILISATEUR u ON d.numCompetiteur = u.numUtilisateur
JOIN CLUB cl ON u.numClub = cl.numClub
WHERE d.numConcours = 1
GROUP BY d.numDessin, d.titre, u.nom, u.prenom, cl.nomClub
ORDER BY moyenne DESC;

Requête 8 (libre) — Taux de participation par concours

Nombre de compétiteurs inscrits par concours et pourcentage de participation par rapport au total des compétiteurs enregistrés.

SELECT
    co.numConcours,
    co.theme,
    co.etat,
    COUNT(icc.numCompetiteur) AS nb_competiteurs,
    (SELECT COUNT(*) FROM COMPETITEUR) AS total_competiteurs,
    ROUND(
        COUNT(icc.numCompetiteur) * 100.0
        / (SELECT COUNT(*) FROM COMPETITEUR), 1
    ) AS taux_participation_pct
FROM CONCOURS co
LEFT JOIN INSCRIPTION_COMPETITEUR_CONCOURS icc
    ON co.numConcours = icc.numConcours
GROUP BY co.numConcours, co.theme, co.etat
ORDER BY co.numConcours;

Requête 9 (libre) — Dessins en attente d'évaluation complète

Concours en attente dont certains dessins n'ont pas encore été évalués par 2 évaluateurs, avec le nombre d'évaluations manquantes.

SELECT
    co.numConcours,
    co.theme,
    d.numDessin,
    d.titre,
    COUNT(ev.numEvaluateur) AS nb_evaluations,
    (2 - COUNT(ev.numEvaluateur)) AS evaluations_manquantes
FROM CONCOURS co
JOIN DESSIN d ON co.numConcours = d.numConcours
LEFT JOIN EVALUATION ev ON d.numDessin = ev.numDessin
WHERE co.etat = 'attente'
GROUP BY co.numConcours, co.theme, d.numDessin, d.titre
HAVING COUNT(ev.numEvaluateur) < 2
ORDER BY co.numConcours, d.numDessin;

Requête 10 (libre) — Évaluateurs les plus chargés par concours

Liste des évaluateurs ayant évalué le plus de dessins dans un concours, avec le nombre de places restantes (maximum 8 évaluations).

SELECT
    co.numConcours,
    co.theme,
    CONCAT(u.nom, ' ', u.prenom) AS evaluateur,
    COUNT(ev.numDessin) AS nb_dessins_evalues,
    (8 - COUNT(ev.numDessin)) AS places_restantes
FROM EVALUATION ev
JOIN DESSIN d ON ev.numDessin = d.numDessin
JOIN CONCOURS co ON d.numConcours = co.numConcours
JOIN UTILISATEUR u ON ev.numEvaluateur = u.numUtilisateur
GROUP BY co.numConcours, co.theme, ev.numEvaluateur, u.nom, u.prenom
HAVING COUNT(ev.numDessin) >= 3
ORDER BY nb_dessins_evalues DESC, co.numConcours;

Triggers (5 triggers pour les règles métiers)

Les triggers ci-dessous implémentent les contraintes du cahier des charges qui ne peuvent pas être exprimées par le schéma relationnel seul.

Trigger 1 : Maximum 3 dessins par compétiteur par concours (C5)

Vérifie avant chaque insertion d'un dessin que le compétiteur n'a pas déjà atteint la limite de 3 dessins dans ce concours.

DELIMITER //
CREATE TRIGGER trg_max_3_dessins_par_competiteur
BEFORE INSERT ON DESSIN
FOR EACH ROW
BEGIN
    DECLARE nb_dessins INT;
    SELECT COUNT(*) INTO nb_dessins
    FROM DESSIN
    WHERE numCompetiteur = NEW.numCompetiteur
      AND numConcours = NEW.numConcours;
    IF nb_dessins >= 3 THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT =
            'Un compétiteur ne peut pas déposer plus de 3 dessins dans un même concours.';
    END IF;
END //
DELIMITER ;

Trigger 2 : Maximum 8 évaluations par évaluateur par concours (C2)

Vérifie qu'un évaluateur ne dépasse pas 8 évaluations pour un même concours. Le trigger joint avec la table DESSIN pour retrouver le concours concerné.

DELIMITER //
CREATE TRIGGER trg_max_8_evaluations_par_evaluateur
BEFORE INSERT ON EVALUATION
FOR EACH ROW
BEGIN
    DECLARE nb_evals INT;
    DECLARE v_numConcours INT;

    SELECT numConcours INTO v_numConcours
    FROM DESSIN WHERE numDessin = NEW.numDessin;

    SELECT COUNT(*) INTO nb_evals
    FROM EVALUATION ev
    JOIN DESSIN d ON ev.numDessin = d.numDessin
    WHERE ev.numEvaluateur = NEW.numEvaluateur
      AND d.numConcours = v_numConcours;

    IF nb_evals >= 8 THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT =
            'Un évaluateur ne peut pas évaluer plus de 8 dessins dans un même concours.';
    END IF;
END //
DELIMITER ;

Trigger 3 : Maximum 2 évaluations par dessin — Jury de 2 (C3)

Empêche qu'un dessin reçoive plus de 2 évaluations, garantissant la composition du jury de 2 évaluateurs.

DELIMITER //
CREATE TRIGGER trg_max_2_evaluations_par_dessin
BEFORE INSERT ON EVALUATION
FOR EACH ROW
BEGIN
    DECLARE nb_evals_dessin INT;
    SELECT COUNT(*) INTO nb_evals_dessin
    FROM EVALUATION
    WHERE numDessin = NEW.numDessin;
    IF nb_evals_dessin >= 2 THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT =
            'Un dessin ne peut pas avoir plus de 2 évaluations (jury de 2).';
    END IF;
END //
DELIMITER ;

Trigger 4 : Le président ne peut pas être compétiteur de son concours (C4)

Vérifie avant l'inscription d'un compétiteur à un concours que ce compétiteur n'est pas le président du concours.

DELIMITER //
CREATE TRIGGER trg_president_pas_competiteur
BEFORE INSERT ON INSCRIPTION_COMPETITEUR_CONCOURS
FOR EACH ROW
BEGIN
    DECLARE v_president INT;
    SELECT numPresident INTO v_president
    FROM CONCOURS WHERE numConcours = NEW.numConcours;
    IF NEW.numCompetiteur = v_president THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT =
            'Le président d un concours ne peut pas être compétiteur de ce même concours.';
    END IF;
END //
DELIMITER ;

Trigger 5 : Un évaluateur ne peut pas concourir dans le même concours (C8)

Vérifie qu'un utilisateur inscrit comme évaluateur d'un concours ne peut pas s'inscrire comme compétiteur du même concours.

DELIMITER //
CREATE TRIGGER trg_evaluateur_pas_competiteur
BEFORE INSERT ON INSCRIPTION_COMPETITEUR_CONCOURS
FOR EACH ROW
BEGIN
    DECLARE nb_eval INT;
    SELECT COUNT(*) INTO nb_eval
    FROM INSCRIPTION_EVALUATEUR_CONCOURS
    WHERE numEvaluateur = NEW.numCompetiteur
      AND numConcours = NEW.numConcours;
    IF nb_eval > 0 THEN
        SIGNAL SQLSTATE '45000'
        SET MESSAGE_TEXT =
            'Un évaluateur d un concours ne peut pas concourir dans ce même concours.';
    END IF;
END //
DELIMITER ;
